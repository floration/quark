# 1.18.3

A server update: dedicated servers use far less CPU, and a server that can't keep its tick rate steady now lowers it by itself. Gameplay is unchanged and the network protocol is unchanged (42), so 1.18.3 plays with 1.18.2 games and servers.

## Servers
- **Much less CPU.** A Linux server with players on used about 30% of a CPU core on a small cloud VM. It now uses 10-12%. It sleeps until just before each tick instead of spinning, and it reads and sends its packets in batches. Each tick also costs 20-30% less: cheaper visibility checks, snapshot packing, bot thinking and lag compensation.
- **Late ticks lower the tick rate.** If ticks keep running more than about 4 ms late (a busy or shared host), the server steps down to 500, 250 or 125 Hz at the next break. Before, it only did this when its own CPU use was high, so a slow shared VM stayed at 1000 Hz and played badly.
- **Short on bandwidth lowers the snapshot rate first** (500, 333, 250, 125 a second), then the tick rate. It reacts to most players losing packets or lagging at once, or to a host's `--max-upload-kbps` limit. One player's bad connection no longer lowers the rate for everyone.
- The server console's `status` shows the tick and snapshot rates, how late ticks run, the upload and download, and why the rate last changed.
- New server options: `--max-upload-kbps N` and `--tick-spin auto|N`.

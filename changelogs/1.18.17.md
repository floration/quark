# 1.18.17

You can now change how a game mode plays, not just its numbers. The built-in modes play exactly as before.

## Custom modes
- **Mode logic**: a custom mode (`.qmode`) can now carry a `logic` section that changes what happens when: what a kill scores, when a round ends and who wins it, respawns, who can hurt whom, timers and announcements. It starts from one of the 13 built-in modes and only overrides what it writes. The bomb, the payload cart, capture points, race checkpoints and the other objective mechanics stay as they are; the logic decides what they mean.
- **Host > Custom modes** shows **LOGIC: name#1a2b3c4d** under the TIME / SCORE / ROUNDS sliders for a mode with logic (or the error, in red, when it doesn't compile). Saving a mode there keeps its logic and any settings this version doesn't know (another editor's, a newer game's) instead of dropping them.
- A server playing mode logic says so: its name in the server list starts with `[name#1a2b3c4d]`, the CUSTOM MODE notice on joining shows the same label, and the server log names it. Two servers with the same label play the same rules. A mode whose logic doesn't compile won't start, and says which line is wrong.
- **Where it runs**: games you host with a custom mode (unranked). Ranked matches and time trials always play the standard rules.
- Players joining need nothing extra: the logic runs only on the server, the network protocol is unchanged, and the HUD is the base mode's.

## Gamemode editor (for mode makers; not in the game download)
- A new local page for making modes: `tools/mode_editor` (http://127.0.0.1:8771/). Start from any built-in mode and edit it as code, blocks, a graph or a table of values; see what changed against the built-in, which phase each part runs in, and simulate matches with bots. Saving keeps the physics editor's movement settings in the same file untouched.

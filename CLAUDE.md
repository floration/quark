# Working on quark

- Commit each change locally when it's done and tested, but do NOT push until the owner says to push (they batch fixes so fewer releases go out). When told to push, push all the local commits together.
- Before committing: build (`cmake --build build -j`) and run `build/quark_tests` (headless multiplayer tests must pass).
- Client changes can be checked headless: `Xvfb :99 &` then `DISPLAY=:99 build/quark --host ffa --map bastion --screenshot out.png`.
- Weapons and movement in `src/game/gamedefs.h` / `src/game/pmove.cpp` are placeholders until the owner specifies them.

## Priorities
- Performance and latency come first, above all else. Judge frame rate by 1% and 0.1% lows (frame-time spikes), not averages.
- Whenever a feature, the render pipeline, netcode or anything else can be made faster or lower-latency, do it.
- In-game F3 overlay shows avg / 1% low / 0.1% low FPS; use it (and `--screenshot` runs) to check changes.

## Releases, versions, changelogs
- All work is pushed to the `testing` branch (not the default branch). `.github/workflows/release.yml` builds and tests every push on every branch (Linux tests, Windows tests on a Windows runner, macOS build) but publishes from two places only:
  - **TESTING**: a push to `testing` publishes a signed GitHub *prerelease* tagged `test-<VERSION>-test.<run number>`, built as version `<VERSION>-test.<run number>` (never "latest"; the website isn't redeployed; the tag must never start with `v<digit>` or a digit, or launchers 0.12-1.16 would install it). macOS is optional there: the prerelease goes out with Windows + Linux and the macOS files are added when that build succeeds. The launcher's TESTING channel and the Discord testing channel follow these.
  - **PRODUCTION**: only a tag `v<VERSION>` (exactly; no suffix) pushed on a commit of the protected default branch, which is only updated by a PR from `testing`. It needs Windows, Linux AND macOS green (no macOS runner = no release), fails if that release already exists, publishes it as latest, then deploys `site/` to https://floration.github.io/quark. Dedicated servers auto-update to production only.
  - Any other branch: build + test only. Keep the workflow passing.
- To ship production (owner): merge the `testing` → default-branch PR, then `git tag v<VERSION> <merge commit> && git push origin v<VERSION>`.
- Every update: bump `VERSION` (semver; started at 0.1.0) and add `changelogs/<VERSION>.md` describing what changed. The release notes, the website and the launcher all show that file (a production tag without it fails).
- Every qpak and the release manifest `quark-release.txt` are signed with `QUARK_SIGNING_KEY` (docs/SIGNING.md); each platform's qpak also carries its `quark_launcher`. Actions are pinned by commit SHA (Dependabot bumps them); keep `persist-credentials: false` and write permissions only on the release / pages jobs.
- The launcher (`src/launcher/`) installs/updates from the release's `quark-<platform>.qpak` (made by `tools/pack.py`); keep those asset names stable.

## Maps
- Map pool (each map is built for ONE mode, its `for` line, and declares a `# setting`): ranked maps temple (vanilla 1v1), furnace and dojo (vampire 1v1; dojo has `holdfire 5`: both start facing, no firing for 5 s), gantry (instagib, a 5 min FFA, built for ffa), anvil (all three); mode maps clockwork=duel, depot=bomb, summit=koth, downtown=koth, railyard=payload, canal=npayload, harbor=ffa, bastion=vs, orbital=vs, colosseum=tourney, foundry=tag, hamlet=hide, hightown=hide (a skyscraper over a city: offices round an atrium, big switchback staircases along the west and east facades, a roof terrace), viaduct=race, lodestone=points, midtown=points (multi point: an attack down five points with staged spawns). Each map is offered for its own mode plus FFA (`modes` line, written by make_maps.py); Lodestone alone is built for every mode (not the ranked race). Any map can still be started in any mode: the menus warn it may not work. No map is named after a game mode. `wallbang` brushes are dark grey and let hitscan through for half damage. Maps are a build artifact: `tools/make_maps.py` writes them into `maps/` at build time (a CMake step, python3 only; deterministic output) and `maps/*.qmap` is not in git. To change a map, edit `make_maps.py` and rebuild; never hand-edit or commit the generated .qmap files (a hand-made map that should ship needs a `!/maps/<name>.qmap` line in .gitignore). `tools/embed_maps.py` embeds the generated maps plus any hand-made map un-ignored in `.gitignore` (names + sha256 for ranked, and the text) at build time; stray files in `maps/` are ignored. `for <mode>` in a map marks the mode it's built for; menus pick that map by default. Why each map suits its mode and why each structure is there: `docs/MAP_STRUCTURES.md`.
- `quark_tests` checks every map: spawns not in walls, preferred mode supported, bots can navigate from every spawn to every objective, every ladder climbable, every staircase walkable and not cutting a path, and every map scoring >= 7 in decor / layout / movement / creativity / mode fit / balance (`build/quark_tests mapreport` writes `docs/MAP_REPORT.md`; metrics in `docs/MAP_METRICS.md`). Grade strictly; don't loosen a metric to pass a map.

## Asset Studio (the owner replaces AI-made assets with human-made ones)
- Page: https://claude.ai/artifact/JuDQckiZY15XUHz1xbD3pC (source `tools/studio/index.html`, files built by `tools/studio/build.py` from `build/quark_tests exportassets build/assets_export`). It lists every default asset; the owner uploads replacements there.
- Before every push: read the page's `replacements` collection (ArtifactData list). For each doc with status `waiting`: fetch the upload (Artifact read with `path` = its `assetBlobId`; it's JSON `{assetId, target, filename, mime, data: base64}`), decode it into `assets/overrides/<target>` (keep the uploaded file's extension), build, test, and mention it in the changelog. Then set the doc's status to `shipped` (with `shippedIn: <VERSION>`).
- After every push (or when maps / sounds / models change): rebuild the studio files and republish the page to the same URL so it shows the current defaults and any new assets.

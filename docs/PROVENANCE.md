# Asset provenance: which assets are human-made

The owner's goal is a game whose every asset is human-made. The provenance registry records, for every asset, whether
it is AI-made or human-made, so the editor dashboard can list what is left and every release's notes can say how far
along it is.

## Files

`assets/provenance/<category>.json`, one file per category (so two editors never write the same file):

| Category file | Items (the `id`) |
|---|---|
| `sounds.json` | `sounds/<kit>/<SOUND>.wav` (the export / override path, docs/ASSETS.md) |
| `voices.json` | `voices/<voice>/<LINE>.wav` |
| `models.json` | `models/<group>/<NAME>.gltf` |
| `maps.json` | `maps/<name>.qmap` |
| `fonts.json` | `fonts/<file>` |
| `images.json` | `images/<file>`, `website/<file>` |
| `ui.json` | `ui/<page>`: one item per menu page and HUD element (below) |
| `bots.json` | `bots/<area>`: one item per bot brain area (below) |

**UI pages** (`sync` reads them from the source, no build needed): the page paths the UI test uses
(`Game::uiScreenPath` in src/client/uitest.cpp and every `UiExp::nav(...)` target), each page counted once wherever it
opens from: `ui/main`, `ui/join`, `ui/host`, `ui/vsbots`, `ui/settings`, `ui/settings/<sub>` (controls, crosshair,
hud, visuals ...; the same pages in game), `ui/pause`, `ui/pause/<sub>`, `ui/picker/<list>` (maps, modes, ladders ...,
one per list), `ui/info/<tab>`, `ui/custom/<tab>`, `ui/leaderboard`, `ui/demos`, `ui/connecting`, `ui/console`,
`ui/editor`, `ui/editor/<prompt>`, plus `ui/hud/<element>` for each HUD element and overlay (health, crosshair,
kill-feed, scoreboard, chat, ...: the `HUD` list in tools/provenance.py). A page an editor names (the UI customizer's
sidecar) is merged in under its own id and kept by `sync`.

**Bot areas** (the bot editor's brain units): `bots/body/nav`, `bots/body/safety`, `bots/body/aim-hand`,
`bots/body/airstrafe`, `bots/perception`, `bots/aim`, `bots/weapons`, `bots/fight-movement`, `bots/roam`,
`bots/targeting`, and `bots/mode/<mode>` for every game mode (`modeName` in src/game/gamedefs.h: vs, bomb, race, koth,
payload, ffa, npayload, duel, 1v1, tourney, hide, tag, points). A user brain adds `bots/brain/<name>`; `sync` never
drops a `bots/` id.

Each file:

```json
{
  "format": 1,
  "category": "sounds",
  "items": {
    "sounds/default/HIT.wav": { "origin": "ai", "source": "synthesized in src/client/audio.cpp" },
    "sounds/heavy_metal/HIT.wav": { "origin": "third-party", "source": "Kenney Impact Sounds (CC0), mixed by tools/import_sfx.py" },
    "sounds/default/ROCKET.wav": { "origin": "human", "by": "q", "date": "2026-10-24", "tool": "sound-editor", "version": "1.19.0" }
  }
}
```

Every asset the game has is listed (ids sorted). Fields:

- `origin` (required): `ai` (made by an AI or generated by a script an AI wrote), `human` (made by the owner or
  another person for Quark), or `third-party` (made by people, from an outside pack or font, under its licence).
- `source`: where it came from (generator, pack, licence, file).
- `by`, `date` (YYYY-MM-DD), `tool` (which program made the change: `sound-editor`, `model-editor`, `map-editor`,
  `bot-editor`, `ui-customizer`, `dashboard`, `asset-studio`), `version` (the first version it shipped in).
- `wip`: a short note when a human replacement is being worked on but hasn't shipped.
- `note`: anything else.
- `evidence` (written by `sync`): the repository file that made it `human` (an override or a custom recording); when
  that file goes, the next `sync` reads the item again (back to `ai`).

Unknown fields are kept as they are. `human` and `third-party` both count as human-made; the summary shows the two
apart.

## Rules

- A new asset starts as `ai` unless the repository shows otherwise.
- Evidence the tool applies by itself (`tools/provenance.py sync`): a file at the asset's path in `assets/overrides/`,
  a recording in `assets/sfx/custom/`, or a map with a `handmade` line makes that item `human`. A HEAVY METAL /
  MAGICAL / MOUTH sound that tools/import_sfx.py's `KITS` table mixes from Kenney clips is `third-party` (CC0,
  assets/sfx/CREDITS.md); one it mixes only from the owner's recordings (MOUTH's hitsound tiers) is `human`; a sound a
  kit doesn't have falls back to DEFAULT's (synthesized: `ai`). Fonts with an OFL file next to them are `third-party`.
  Removed assets are dropped; new ones are added as `ai`.
- **Curated entries**: an entry with `by`, `date` or `tool` was set by a person or an editor (a merge, the
  dashboard), and `sync` never changes it (it still drops it when the asset is gone, except `ui/` and `bots/` ids).
  Every other entry is the tool's reading of the repository, worked out again on each `sync` (its `wip`, `note` and
  unknown fields are kept).
- Never mark an asset `human` that a person didn't make. The owner can mark items in the editor dashboard.

## Editors: the sidecar

The editor dashboard (`tools/editor_dashboard/`, README there) shows pending sidecar entries and writes the owner's
own marks to `Quark\editor-dashboard\provenance.json` (tool `dashboard`), never into a git clone.

A local editor (sound, model, map, bot editor, UI customizer) doesn't edit the registry in the repository. When it
exports something, it writes or updates `provenance.json` in its own folder on the owner's PC
(`Quark\<editor>\provenance.json`):

```json
{
  "format": 1,
  "tool": "sound-editor",
  "items": {
    "sounds/default/ROCKET.wav": { "origin": "human", "by": "q", "date": "2026-10-24", "note": "re-recorded" }
  }
}
```

Same item fields as the registry, keyed by the same ids (any category). Keep one entry per id, the latest export
wins; set `origin` to what the export really is (an edit of an AI asset by the owner is `human` only when the owner
made the sound / model / map; a trim of the AI default stays `ai` with a `note`). The editor dashboard shows sidecar
entries that aren't in the registry yet as pending; `tools/provenance.py merge <sidecar>...` folds them into the
registry before a push (the sidecar's `tool` goes on each entry that has none, so they stay curated; ids not in the
registry yet are added).

## Tool

```
python3 tools/provenance.py sync [<export dir>]    # add / drop items from the asset export's manifest.json + evidence
python3 tools/provenance.py merge <sidecar.json>... # fold editor sidecars into the registry
python3 tools/provenance.py summary [--markdown]    # human vs AI, overall and per category
python3 tools/provenance.py check                   # files parse, ids unique, origins valid (CI meta job)
```

`sync` takes the asset export (`build/quark_tests exportassets build/assets_export`; check the `site` branch out
into `site/` first, or the export has no website pictures and the registry's are kept). Without an export it keeps the
file assets as listed and only reads the evidence and the source again. The files are written one item per line, ids
sorted, so a change is a one-line diff.

**Counting**: every item counts one, whatever it is (a sound, a voice line, a model, a map, a font, a picture, a UI
page, a bot area). Human-made = `human` + `third-party`. The percentage is rounded down to 0.1 (100% only when every
item is human-made).

Every release's notes (testing prereleases and production releases) end with the `summary --markdown` lines, added by
the publish steps in `.github/workflows/release.yml`, e.g.:

```
**Human-made assets: 17.1%** (93 of 542: 31 by the team, 62 third-party) · AI-made 82.9%

Human-made by category: sounds 90/165 · voices 0/210 · ... Every sound, voice line, model, map, font, picture, UI page and bot area counts as one item (assets/provenance/).
```

They show where the GitHub release body is shown: the release page, the launcher's changelog (ASCII: `·` becomes
`-`), the Discord bot's update posts and `/changelog`, and the website's testing updates page. The website's home page
and `updates/` pages are made from `changelogs/*.md` and don't show it. CI's meta job runs `check`.

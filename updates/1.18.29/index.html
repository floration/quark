Update

quark 1.18.29

Everything that changed in this version, and why.

Settings > HUD (src/client/game.cpp, game.h, ui.h)

  • The HUD tab previews the HUD live. The owner: "you should be able to see the UI in real time while you are editing it". Settings in a match hid the HUD (1.18.13's redesign, so it didn't cut through the opaque panel) and the main menu had none, so every offset, size and colour change was blind. Now, on the HUD tab only (not the widget editor or the other tabs, which are unchanged):
    • In a match the HUD draws with live values under the settings: crosshair, health, weapon name, cooldown bars and speed meter (drawn while paused here only), weapon list, sticky counter, and the verbose block, key overlay and custom widgets when they're on. The score box, kill feed and chat stay off (they'd sit under the tab row). The world is dimmed 0.25 instead of 0.55. While dead it uses the sample values.
    • From the main menu the same elements draw at their real places with sample values: 100 health, the first slot's weapon, full bars with 2 dash pips, 12 m/s, FFA's weapon list, the key overlay when VERBOSE INFO is on.
    • The panel is 0.6 alpha on this tab (1.0 elsewhere), so elements under it show through and its text stays readable.
    • The selected element gets a thin pulsing accent outline over everything (a dim dashed one when SHOW is off; none for the 3D weapon model). While one of its sliders is held, and for 1.5 s after any change to it or picking it, it is drawn again over the panel at full strength.
  • How: each element's drawing moved into a helper that takes its values and can return its screen rectangle without drawing (drawHudHealth, drawHudWeaponName, drawHudBars, drawHudSpeed, drawHudSlots; drawKeyOverlay gained sample / draw flags). The live HUD calls the same helpers with the same values, so its per-frame work is unchanged; the preview's extra work (sample values, outline rectangles) only runs while the HUD tab is open. Ui::sliderHeld() tells the preview a slider is being dragged.
  • Screenshot runs: --settingstab hud/<health|weapon|bars|speed|slots|keys> opens the tab with that element picked.

Docs

  • docs/RELEASE_CHECKLIST.md: the settings shell lines say the HUD tab shows the HUD; a "live preview" check on the HUD tab line.

Known

  • At their default place the weapon list and weapon name's bottom row sit behind the settings footer's BACK / RESET WHOLE HUD buttons, which stay opaque; picking the weapon list draws it over them.

Compatibility

  • Client only, no protocol change (still 44).
